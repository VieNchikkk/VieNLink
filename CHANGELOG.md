# История изменений

## 1.3.22 — Windows и Android, 23.11.2026

- **Исправлено ложное «сервер нерабочий» при маршруте «только сайты из списка».**
  Проверка через активный туннель всегда ходила на Cloudflare/YouTube; при таком
  маршруте эти адреса идут напрямую, проверка не проходила, и рабочие серверы
  переключались/отсеивались. Теперь проверяется первый сайт из вашего списка
  (ПК и Android), а провал проверки через туннель больше не меняет `Status`/`FailCount` —
  статус меняет только прямая проверка в скрытом ядре.
- На ПК при сервисном или ручном подключении сервер, не открывший конкретный сервис,
  больше не помечается мёртвым: он просто пропускается до следующей прямой проверки.

## 1.3.21 — Windows и Android, 23.11.2026

- **Исправлен краш «Подключение» из отсева.** Файл отсева хранил `ProxyNode` напрямую,
  а поле `OutboundJson` в нём `[JsonIgnore]` — после загрузки конфиг получался без
  серверов и падал с `InvalidOperationException: Нет серверов для запуска прокси`.
  Теперь отсев хранится через `CachedNode` (как кэш), со старым форматом 1.3.19
  совместим: ссылка разбирается заново.
- Подключение из отсева собирает TUN-конфиг (как обычное VPN-подключение) и убирает
  сервер из отсева только после того, как VPN действительно запустился.
- Переработан внешний вид экрана отсева на Android (сводка, метрики, фильтры, карточки).

## 1.3.20 — Windows и Android, 23.11.2026

- **Исправлено «Подключение» из отсева на Android.** Конфиг собирался без TUN
  (`TunnelMode.SystemProxy`), поэтому VpnService стартовал, но трафик не перехватывался.
  Теперь конфиг для отсева строится как обычное VPN-подключение: TUN, все приложения,
  DNS через сервер.
- Сервер убирается из отсева не сразу, а через 3 секунды — только если VPN действительно
  перешёл в состояние «работает». Иначе он остаётся в отсеве.

## 1.3.17 — Windows и Android, 23.11.2026

- **Добавлены проверенные источники серверов (ПК и Android).** `free-nodes` (ежедневный
  `sub`), `0xRadikal` (Clash), `SoliSpirit configs`, `hamedcode`, `AutoAiVPN`,
  `V2ray-Collector (Bahemmat)`, `ConfigV2Ray (Jafar)`, `node-sub-zixf`, `zhuhaiuk free-nodes`.
  Новые источники подхватываются при запуске обоих клиентов.
- **Иконка «доверенный источник».** Источник, у которого дата публикации файла/репозитория
  не старше 24 часов, помечается ✓ в списке источников ПК и значком `✓ ДОВЕРЕННЫЙ`
  на Android. Дата берётся из GitHub (последний коммит файла, затем push репозитория)
  и обновляется при каждом сборе.
- **Новая вкладка «Отсев — Перепроверка».** Рабочие серверы, переставшие работать,
  больше не теряются: они сохраняются в `nodes-rejected.json`. На вкладке видны счётчики
  по сервисам (YouTube, Telegram, Discord, универсальный), фильтр по сервису и кнопки
  «Подключение», «Отмена», «Следующий», «Вернуть (В рабочие)», «Перепроверить выбранный»,
  «Перепроверить всё» и «Убрать из отсева». Успешно перепроверенный сервер возвращается
  в рабочие.
- **Источники без даты публикации удаляются.** Больше не добавляем и не ищем в источниках,
  у которых нельзя определить дату публикации: подписки-сайты, веб-каталоги и прочие
  не-GitHub списки. Telegram/MTProto-источники и личные подписки не затрагиваются.
  При ошибке GitHub API источник временно пропускается, но не удаляется.
- **Окно свежести настраивается.** «Настройки → Автоматические работы → Считать источник
  свежим, ч» (ПК) и поле «Свежесть источников, ч» (Android). По умолчанию 24 часа;
  источники старше окна пропускаются, источники без даты удаляются.
- **Удалён устаревший источник `Kwinshadow mix`** (репозиторий не обновлялся с марта).
  Он удаляется и у существующих пользователей при загрузке списка.

## 1.3.16 — Windows и Android, 23.11.2026

- **Непроверенный сервер проверяется один раз: не прошёл — удаляется.** Раньше ему
  давались две попытки. Теперь первый же неудачный результат (полная проверка или
  TCP-отсев) убирает его из списка, чтобы не копить мусор.
- Рабочий сервер по-прежнему переживает первый провал и удаляется после двух подряд:
  второй шанс остаётся только у серверов, которые уже доказали работу.

## 1.3.15 — Windows и Android, 23.11.2026

- **Сервер удаляется после 2 провалов подряд** (было 5). Первый провал рабочий сервер
  переживает и сохраняет результат последней удачной проверки; второй подряд — `Dead`
  и удаление. Непроверенный сервер тоже удаляется после 2 провалов. Успешная проверка
  по-прежнему обнуляет счётчик.
- Список серверов теперь очищается быстрее: меньше «полуживых» записей висит в кэше.
  TCP-отсев для рабочих серверов по-прежнему не засчитывается как провал.

## 1.3.13 — Windows и Android, 23.11.2026

- **Выключенный авто-сбор серверов больше не обходится автопоиском источников.**
  Раньше «Автопоиск новых источников» не только добавлял источники, но и сразу
  подмешивал найденные из них серверы — из-за этого казалось, что переключатель
  «Авто-сбор серверов из источников» не работает. Теперь при выключенном авто-сборе
  автопоиск добавляет только источники; серверы не добавляются. Ручная кнопка
  «Найти новые источники» по-прежнему добавляет и серверы.
- **Выключение авто-сбора не удаляет уже собранные серверы.** Оно останавливает
  только пополнение списка. Старые серверы уходят после проверок: непроверенный —
  после 2 провалов, рабочий — после 5 подряд. Если нужно уменьшить список сразу,
  нажмите «Проверить серверы» или очистите кэш в настройках.

## 1.3.12 — Windows и Android, 23.11.2026

- **Сбор серверов стал актуальным: GitHub-источники старше 24 часов пропускаются.**
  Это касается не только автопоиска новых источников, но и самого сбора серверов:
  при обновлении списков проверяется дата последнего коммита файла, а если её получить
  не удалось — дата последнего push репозитория. Если она старше 24 часов, источник
  в этом проходе не загружается. В журнале видно `пропущен — репозиторий старше 24 ч`,
  старые серверы источника при этом не удаляются.
- **Если даты публикации нет, источник собирается как раньше.** Подписки, Telegram
  и обычные сайты без даты не фильтруются; личные источники тоже. Если GitHub API
  недоступен, фильтр не срабатывает — сбор продолжается, чтобы не остаться без серверов.
- Ручное «Обновить выбранный» по-прежнему загружает конкретный источник независимо
  от его возраста — удобно, если нужно проверить старый список вручную.

## 1.3.11 — Windows и Android, 22.11.2026

- **Автопоиск источников: GitHub-репозитории только за последние 24 часа.**
  При поиске новых источников берутся репозитории, у которых последний push был
  не раньше 24 часов назад. Это отсекает старые «свалки» конфигов, из которых почти
  не приходит живых серверов. Если время публикации отсутствует или не разбирается,
  источник не отсеивается (как и раньше). Публичные сайты проверяются без этого фильтра:
  у них нет единой даты публикации.

## 1.3.10 — Windows и Android, 22.11.2026

- **Статистика источников: добавлено «Рабочих всего».** Помимо «Всего» (уникальные
  серверы за всё время) и текущих «Рабочих», видно, сколько уникальных серверов

## 1.3.9 — Windows и Android, 22.11.2026

- **Статистика источников: «Всего» и «Рабочих».** В списке источников на ПК две колонки:
  «Всего» — сколько уникальных серверов когда-либо пришло из источника (повторный сбор
  не увеличивает число), «Рабочих» — сколько из них сейчас в статусе «рабочий».

  «Всего» заполняется по уже собранному кэшу при первом запуске. Счётчики обновляются
  после проверок и сборов, раз в минуту и при открытии списка источников.
- **Windows: отдельные переключатели автоматических работ.** В настройках появился раздел
  «Автоматические работы»: автопоиск источников, авто-сбор серверов, обновление подписок
  при запуске, автосбор и проверка MTProto, автообновление ядра sing-box, автопроверка
  обновлений приложения; автопроверка серверов и её параметры — рядом. Каждую работу можно

- **Windows: обновление приложения видно и управляется вручную.** В «Общих» рядом
  с версией появилась кнопка «Проверить обновление», строка статуса и кнопка
  «Скачать и установить» (после скачивания — «Запустить установщик»). Скачивание
  показывает процент, его можно отменить кнопкой «Отменить». Установщик запускается
  обычным окном (`/CLOSEAPPLICATIONS /NORESTART`), а не `/SILENT`: виден ход установки,
  а в конце можно сразу запустить новую версию. Путь к установщику остаётся в «Общих»,
  так что установку можно отложить.
- **Android: журнал переехал в «Инструменты», а «Настройки» заняли его место в нижнем меню.**
  Нижние вкладки теперь «Подключение / Обход / Инструменты / Настройки». Журнал открывается
  плиткой в «Инструментах» (отдельный экран с «Поделиться», очисткой и логом ядра).
  В «Настройках» появились переключатели автоматических работ: автопоиск источников,
  авто-сбор серверов, автопроверка серверов, автосбор и проверка MTProto, автопереключение
  при сбое и автопроверка обновлений приложения.

## 1.3.8 — Windows и Android, 22.11.2026

- **Android: ядро проверки выходит в сеть.** Процесс `:probe` не получал сетевой интерфейс
  (ядро писало «missing default interface») и потому не мог проверить ни один сервер.
  Теперь он берёт интерфейс по умолчанию из `ConnectivityManager` сам, без VPN-службы.
- **Android: «нашёл N» в ходе проверки — это новые серверы за партию**, а не число
  повторно подтверждённых рабочих.
- **Квота на сервис поднята до 5** (YouTube, Telegram, Discord, универсальный): пока сервис
  ниже порога, автопоиск ищет под него.
- **Android: результаты прошлой проверки применяются один раз** (устранено двойное
  применение при старте), а автозапись списка и ручное добавление сервера больше
  не перезаписывают друг друга (`SaveNodes` под общим замком).

- **Android: рабочие серверы загружаются из своего файла первыми и сразу перепроверяются.**
  Порядок на запуске: `nodes-working.json` → перепроверка рабочих («Старт: рабочие
  перепроверены — 7, живых 7») → и только потом поиск новых и квоты. Рабочий список
  переживает перезапуск и не собирается заново поиском.
- **Рабочие серверы не пропадают из списка из-за проверок.** Результат последней удачной
  проверки сохраняется все 5 попыток: сервер удаляется только после 5 провалов подряд,
  а не после первого/третьего. Непроверенный — после второго подряд.
- **Счётчики в шапке считают по одной базе.** Общее число рабочих и значки сервисов берут
  серверы рабочего списка с подтверждённым доступом (свежесть проверки в счётчиках
  не учитывается, иначе они «таяли» бы сами по себе). Один сервер может открывать
  несколько сервисов, поэтому сумма значков больше общего числа.
- **Android: рабочее и непроверенное хранится отдельно.** Проверенные серверы лежат
  в маленьком `nodes-working.json` и переписываются после каждой проверки, а куча
  непроверенных — в общем кэше, не чаще раза в минуту.
- **Android: значок «рабочих серверов» показывает содержимое списка рабочих** —
  ровно то, что сохраняется в `nodes-working.json`. Найденные при проверке рабочие серверы
  сразу попадают в этот список и в файл, поэтому число на значке растёт по партиям,
  а не считается заново по всем найденным. Рядом — «+прибавилось −убыло».
- **Android: во время ручной проверки фоновая не работает.** Пока идёт «Проверить серверы»
  (5 партий), планировщик и обслуживание свои партии не запускают — иначе они отбирали
  `:probe` между партиями и ручной прогон стоял на месте.
- **Android: «Остановить поиск» — только для ручного прогона.** Фоновая проверка больше
  не делает кнопку «стопом»: нажатие «Проверить серверы» всегда запускает ручную проверку
  (фоновая партия при этом уступает место).
- **Рабочие серверы проверяются мягче (Windows и Android).** Первые два провала
  не стирают результат последней удачной проверки — счётчики не скачут из-за разовой
  ошибки сети. Рабочему серверу в проверке даётся вторая попытка, а TCP-отсев
  (грубая проверка на мобильной сети) больше не засчитывается рабочим как провал.
  Удаление — только после 5 провалов подряд, как и раньше.
- **Проверка не замирает на одном сервере:** у клиента Clash API таймаут 10 секунд вместо
  30 и свой предел на запрос задержки (timeout + 2,5 с).
- **Кэш: рабочий сервер с одним провалом больше не выбрасывается при загрузке**
  (Windows и Android): в текущей схеме это не «мусор», а сервер, ждущий перепроверки, —
  он удаляется только после 5 провалов подряд.
- **Windows: то же разделение кэша** (`NodeCacheWriter`): рабочие — в `nodes-working.json`
  после каждой проверки, непроверенные — в `nodes.json` не чаще раза в минуту.
  Правило «рабочий сервер удаляется только после 5 провалов» на ПК работало и раньше
  (скрытая проверка идёт в том же процессе с настоящими объектами серверов).
- **Android: рабочие серверы больше не удаляются после одного провала.** Процесс `:probe`
  разбирал ссылки в новые объекты и не знал прежний статус и счётчик провалов, поэтому
  считал рабочий сервер непроверенным и удалял его с первой неудачи. Теперь статус
  и `FailCount` едут вместе с запросом: рабочий удаляется только после 5 провалов подряд,
  как и на ПК.
- **Android: одно нажатие «Проверить серверы» прогоняет 5 партий по 200** — до 1000 серверов,
  с подписью «Партия 2 из 5» и общим итогом. Остановка прерывает и текущую партию, и очередь.
- **Android: рабочие серверы проверяются отдельным проходом** после поиска новых
  («Проверяю рабочие: 3 из 12»), а не занимают место в партиях поиска.
- **Android: фоновая проверка не забирает `:probe` у ручной** — пока идёт ручной прогон,
  планировщик свои партии не запускает.
- **Android: проверка больше не висит, если `:probe` умер.** Ожидание результата прерывается,
  если счётчики прогресса не меняются 100 секунд (раньше файл прогресса считался
  «живым» и ожидание длилось все 10 минут).
- **Android: приложение больше не зависает на старте и при нажатиях.** Счётчики сервисов,
  выбранный сервер и сводка на экране «Серверы» читают уже готовый снимок списка и не ждут
  разбора кэша или обновления источников. Раньше эти данные ждали общий замок, пока фон

- **Android: убраны нереализованные режимы обхода.** На странице «Обход» больше нет карточек

- **Проверка найденных серверов стала в разы быстрее.** Перед полной проверкой
  мёртвые `host:port` отсеиваются быстрым TCP-опросом (`NodePrecheck`, 96 соединений,
  2 с на адрес, один опрос на endpoint) — в пробное ядро попадают только отвечающие
  адреса. Параллельность полной проверки поднята: 12 в простое, 8 без VPN, 6 при

  ограничен 6 минутами: приложение не висит на «Проверяю серверы» полчаса, а продолжает
  следующим тактом. UDP-протоколы (Hysteria2/TUIC) TCP-отсев не затрагивает.
- **Переключение серверов учитывает выбранный сервис.** Если нажать «Универсальный»
  (или YouTube/Telegram/Discord) и сервер упадёт, следующий выбирается из серверов
  этого же сервиса — сначала лучший по задержке и качеству. Только когда живых
  серверов выбранного сервиса нет, переключение идёт на следующий лучший из другого
  сервиса. При появлении нового сервера выбранного сервиса он встаёт первым в
  приоритете, а при работе на запасном сервере приложение плавно возвращается на него
  (тёплое переключение без перезапуска ядра, если сервер уже в конфиге).
  Правило общее для ПК и Android (`NodeFailover`): свежесть проверки обязательна,
  «Только мои» соблюдается. Кнопка «Сменить сервер» больше не сбрасывает выбранный
  сервис — она ходит по кругу внутри его приоритета.
- **Проверка серверов во время работы VPN больше не удаляет рабочие серверы.**
  Прямая проверка в скрытом ядре (ПК) и в процессе `:probe` (Android) идёт мимо VPN —
  это подтверждено кодом и журналом. Исправлено три причины ложных провалов:
  проверка через поднятый прокси теперь идёт по универсальному Cloudflare и сервису,
  который сервер уже открывал (раньше — только по YouTube, и сервер, работающий через
  Telegram/Cloudflare, браковался и после пяти подключений удалялся); провал проверки
  живости больше не меняет статус сервера — статус и `FailCount` определяет только
  прямая проверка; граница свежести в фоновой проверке пересчитывается в каждом проходе,
  поэтому живые серверы не выпадают из счётчиков на десятки минут.

- Health-check реже (90 с, после сбоя 25–120 с) и адаптивная параллельность проверки.
- Источники при ошибке прокси повторяются напрямую.
- Сбой узла во время операции не теряется — переключение откладывается.
- `sources.dat` шифруется DPAPI; старые открытые копии удаляются.
- Конфиг ядра с UUID удаляется при отключении и выходе.
- Узлы с `tls.insecure` помечаются «⚠» и не выбираются первыми.
- Логи пишут стек исключения; журналы ротируются по 2 МБ.
- `MainWindow` разбит на partial-классы; добавлены golden-тесты и CI.
- Версии схем `settings.json`, `nodes.json` и `mtproto.json`: старые файлы
  мигрируют, новые читаются с предупреждением в журнале — данные не сбрасываются.
