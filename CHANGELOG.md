# История изменений

## 1.3.47 — Windows, 24.11.2026

- **Браузер стал отдельным приложением.** «VieNLink Браузер» (`VieNLink.Browser`) ставится
  и обновляется независимо от VPN: своя версия, свой установщик, свои релизы. Внутри VPN
  кнопка «Браузер» и Ctrl+Shift+B запускают установленный браузер.
- **Локальный канал для панели VPN.** VPN-приложение поднимает named pipe `VieNLink.Vpn`:
  отдаёт состояние (подключён, сервер, задержка, режим обхода) и принимает команды
  (подключиться, отключиться, сменить сервер, zapret, свой движок, открыть окно).
  Браузер не запускает ядро сам — он только просит VPN, поэтому обновления не связаны.
- **Настройки, закладки и история браузера** живут в `%LOCALAPPDATA%\VieNLink` — обновление
  любой из частей их не стирает.
- Android: без изменений (последняя сборка — 1.3.46).
- `versionCode` 10347.

## 1.3.46 — Android, 24.11.2026

- **Исправлено: обновление «из приложения» на телефоне и планшете.** Обновлятор брал
  последний файл `*.apk.sha256` в релизе, а когда в нём два APK (телефон и телевизор),
  телефонный APK сверялся с хешем ТВ-сборки — загрузка падала с «Контрольная сумма APK
  не совпала». Теперь контрольная сумма подбирается по имени выбранного APK.
- **Исправлен резервный путь проверки обновлений.** Когда GitHub API отвечает 403 (лимит
  запросов), обновлятор читает atom-ленту и собирал имя файла как
  `VieNLink-<версия>-android.apk` — такого имени нет с 1.3.38, загрузка заканчивалась 404.
  Теперь имя строится по платформе (`-phone.apk` / `-tv-arm32.apk`), а тег отбирается
  по своей сборке (телефон не видит ТВ-релиз и наоборот).
- Windows: функциональных изменений нет (сборка пересобрана на новой версии).
- `versionCode` 10346.

## 1.3.45 — Windows и Android, 24.11.2026

- **Сбор серверов стал устойчивее и дешевле.** Для raw-контента GitHub добавлены зеркала
  `ghfast.top`/`gh-proxy.com` (раньше зеркала были только у API-дат); даты публикации
  кэшируются на диск (`freshness.json`), а неизменившиеся списки пересобираются по ETag
  (304) без повторного скачивания.
- **Больше серверов и протоколов.** Каналы Telegram теперь собираются и как серверы
  (не только MTProto), при недоступном `t.me` — через RSS-зеркала; добавлен разбор `tuic://`.
- **Автопоиск расширен.** Оживлён обход публичных сайтов (nodefree, freeclashnode и др. —
  дата берётся из адреса статьи); добавлены GitLab и Gitee (свежесть и поиск). На ТВ обход
  сайтов отключён.
- **Чистка источников.** Убраны 9 источников, которые за всё время не дали ни одного
  рабочего сервера. «Бесплодные» источники отключаются и удаляются автоматически, а
  зеркала одного списка (одинаковый контент) — дедуплицируются.
- **Карантин вместо удаления.** Источник без определяемой даты публикации больше не
  удаляется сразу — уходит в карантин и удаляется только после недели. Добавлен общий
  бюджет обращений к GitHub API за сбор.
- **Отсев (ПК и Android).** Подтверждение провала рабочего сервера стало двойным — разовая
  заминка сети больше не засчитывается; причина смерти пишется в отсев и лог. При возврате
  сервера из отсева он сразу попадает в счётчики (свежая отметка проверки) — раньше
  возвращённый сервер «пропадал» из счётчиков.
- **Стартовый набор серверов (seed).** На первой установке приложение подхватывает
  встроенный `seed.txt` с недавно проверенными серверами — не нужно ждать первый сбор и
  проверку. Генерируется режимом `SelfTest exportseed` перед релизом.
- `versionCode` 10345.

## 1.3.44 — Android, 24.11.2026

- **Исправлено: трафик приложений не попадал в VPN на телефоне и планшете.** После
  перехода на Java-платформу (1.3.36+) YouTube/Chrome висели при рабочем сервере:
  в VPN-таблице маршрутов был только собственный подсет `172.19.0.0/30` без
  `default` — DNS доходил (на адрес 172.19.0.1), а TCP приложений шёл напрямую мимо
  TUN. Причина в Java-`openTun` (`VieNLinkJavaBridge`): счётчик маршрутов считал и
  адреса TUN, поэтому защитный `addRoute("0.0.0.0",0)` не срабатывал. Теперь счётчик
  считает только маршруты (как в C#-платформе). Проверено: `default dev tun0` в
  VPN-таблице, трафик идёт `inbound/tun → outbound/vless`.
- Android: `versionCode` 10344.

## 1.3.38 — Android, 24.11.2026

- **YouTube в VPN: картинки и видео.** Лента грузилась, но превью (`i.ytimg.com`,
  `yt3.ggpht.com`) и воспроизведение висели: приложение пробует HTTP/3 (QUIC, UDP/443),
  а через бесплатные серверы QUIC часто не проходит. В конфиг TUN добавлено правило
  `network: udp, port: 443 → reject`: приложения переходят на TCP, как в TUN-обходе.
  `SelfTest checkconfigs` — без замечаний.
- Android: `versionCode` 10338.

## 1.3.37 — Windows и Android, 24.11.2026

- **Исправлено: в TUN не открывались YouTube и Discord при рабочих серверах.** Трафик шёл,
  но TLS-рукопожатие висло: в DNS внутри TUN теперь `strategy: ipv4_only` — приложение больше
  не получает AAAA и не пытается идти по IPv6, маршруты которого в TUN недоступны
  (`::/0 unreachable`). Проверено на планшете: YouTube и Discord открываются через VPN.
- **Обновлятор Android больше не предлагает TV-сборку телефону.** В релизе лежат APK для

  магазинные (`-store`) не участвуют в самообновлении (`AndroidUpdate`, `BuildInfo.IsTelevisionBuild`).
- Android: `versionCode` 10337.

## 1.3.36 — Windows и Android, 24.11.2026

- **Android: Java-платформа libbox стала основной.** `PlatformInterface` и `VpnService`-часть
  ядра работают в Java (`com.vienlink.platform`), C# вызывает их только на старте/остановке.
  На телефоне уход в фон на 30 с и возврат — 0,6 с, ANR и зависаний MonoVM нет.
  Аварийный откат остался: `-p:AndroidJavaPlatform=false`.
- **Новый поиск серверов «от источника».** Партия больше не набирается первыми серверами
  списка: источник без рабочих серверов получает 3 слота, средний — 6, источник с
  подтверждённым выходом — до 10. Оценка источника считается по проверенным серверам.
  Источники с ≥50 проверками и нулём рабочих в фоне не проверяются (ручная проверка
  и «Перепроверить всё» ограничение обходят). На ПК и Android.
- **Телевизор: отдельная сборка** `VieNLink-<версия>-tv-arm32.apk` (`armeabi-v7a`,
  32-битное ядро sing-box 1.14.4 собрано под `android/arm`). Проверено на Xiaomi MiTV:
  запуск с пульта, две колонки, разрешение VPN, TUN-обход (`ping` 0 %), прокси-режим.
- **ТВ: только YouTube и Zona.** Две кнопки быстрого подключения, домены проверки —
  `youtube.com`, `redirector.googlevideo.com`, `az1.zona.pub`, `sync.zonasearch.com`
  (взяты из APK Zona 3.0.79). Telegram, Discord и MTProto на ТВ убраны из интерфейса,
  квот и фоновых проверок. Проверено воспроизведение фильма в Zona через VPN.
- **ТВ: исправлен DNS.** DNS через прокси на доменных адресах серверов зацикливался
  (`DNS query loopback in transport[remote]`) — Zona падала с `UnknownHostException`.
  На ТВ теперь прямой UDP-DNS (77.88.8.8, 1.1.1.1; `ipv4_only`).
- **ТВ-профиль ресурсов:** лимит 1500 серверов, партия 60/6 потоков, `:probe` 6/4,
  квоты 6 и 4, такт 2 мин, обслуживание 60 мин — 1,7 ГБ ОЗУ телевизора хватает.
- **Планшет: две колонки и поворот** (`DeviceProfile`: телефон / планшет `sw600dp+` / ТВ),
  крупные элементы и фокус для пульта на ТВ; телефон остался в портрете.
- **Android 11 (Lenovo TB-J706F):** Release с AOT падал SIGSEGV — AOT отключён
  (`RunAOTCompilation=false`), планшетная сборка проверена.
- Windows: тот же «поиск от источника» в скрытой проверке; сборка без изменений интерфейса.
- Android: `versionCode` 10336.

## 1.3.35 — Windows и Android, 23.11.2026

- **Обход DPI: автоподбор теперь видит видео.** Проверка скачивала 0 байт из
  `videoplayback` (YouTube подписывает поток в JS), хотя в браузере видео шло. Теперь
  после HTTP-проверки вызывается **yt-dlp** (клиент android, скачивается один раз в
  `%LOCALAPPDATA%\VieNLink`): реальные байты ≥64 КБ — стратегия получает `VideoOk`,
  перебор останавливается, профиль пишется с Quality 100. Подтверждено: 629 172 байта
  на стратегии №2 «Фейк + multidisorder, TTL 64, seq настоящий». То же для zapret.
- **Стратегии стали ручными и кликабельными:** плашки стратегий и пресетов переключаются
  нажатием, рядом «Подобрать заново», ручной выбор сохраняется и не подменяется профилем;
  «Только QUIC-фейк» проверяется QUIC-рукопожатием (h3).
- **ПК, оформление:** кнопки с градиентом, тенью и hover/pressed/focus, цветные
  подчёркивания вкладок, шапка без дубля названия сервера; окно фиксированного размера
  **980×680** (края не тянутся, «свернуть/развернуть» работают, позиция запоминается).
- **ПК: рабочие серверы больше не пропадают из кэша** — запись «рабочий» без задержки
  (сервер открыл только Cloudflare) сохраняется, судьбу решает перепроверка.
- **Счётчики в шапке больше не «врут».** Щит и значки сервисов считают по одному правилу
  (`NodeAvailability.IsCountable`): рабочий сервер, у которого последняя удачная проверка
  прошла и нет подтверждённого провала. Числа больше не падают в ноль на каждой
  перепроверке — уменьшает их только подтверждённый провал (и запись старше часа).
- **Кнопка сервиса не отвечает «серверов нет», когда счётчики показывают серверы.**
  Если свежих проверок нет, приложение проверяет эти же серверы скрытым ядром на месте
  (ПК и Android). На Android экран «Серверы» показывает те же «доступные», что и шапка.
- **Android: счётчики обновляются по ходу проверки.** Процесс `:probe` передаёт готовые
  результаты сразу (`probe-live.json`), а не только в конце партии; файл читается лишь
  при изменении и без общего замка — главный процесс меньше нагружается.
- **Android: меньше зависаний.** Возврат из фона больше не пересобирает всю страницу
  (только шапка), `MaintenanceReceiver` не держит главный поток, фоновая проверка не
  блокирует интерфейс.
- **Android, уведомление и шапка:** в уведомлении туннеля и виджете — «Следующий»
  (переключение на следующий проверенный сервер); «Проверить серверы» → [«Авто-проверка» |
  «Поделиться»] → «Сменить сервер» → «Добавить сервер».
- **ПК: строка «В списке: …» снова читается** — получила цвет темы и подсказку про
  «рабочие / доступные / свежие» (была чёрной на тёмном фоне).
- Android: `versionCode` 10335.

  проверяется на 10 потоках: таймауты не занимают канал.
- Android: без функциональных изменений (`versionCode` 10334, чтобы не отставал).

## 1.3.33 — Windows и Android, 23.11.2026

- **Android: при запуске приложение само поднимает VPN на серверы из отсева.**
  После стандартной стартовой перепроверки, если обычный VPN **не** подключён,
  оно по очереди подключается к каждому серверу из отсева, ждёт `VPN работает`,
  возвращает сервер в рабочие и **сразу отключает VPN**, затем переходит к следующему.
  Ничего не удаляется.
- **Если обычный VPN уже подключён — автоподключение не запускается.** На Android
  одновременно может работать только один VpnService, поэтому проверка не имеет
  права переключать пользователя. Ручная «Перепроверить всё» в это время идёт через
  отдельный `:probe` и VPN не трогает.
- ПК: автоперепроверка отсева в скрытом ядре на отдельных портах, без вмешательства
  в текущее подключение.
- Квоты 20/20, 31+8 источников, DNS-исправления сохранены.

## 1.3.32 — Windows и Android, 23.11.2026

- **Перепроверка отсева — без конфликта с обычным подключением.** Она идёт через
  отдельный процесс `:probe`, по одному серверу, с DNS через сам сервер: VpnService

- Квоты 20/20, 31+8 источников, авто-кнопки сохранены.

## 1.3.25 — Windows и Android, 23.11.2026

- **Провал рабочего сервера теперь подтверждается отдельной проверкой.** Если сервер

  из-за нагрузки самой проверки.

  счётчиков остаётся 5 минут. Вернуть 5 в следующем релизе.

  был ложный отсев 1.3.24. Новые записи появляются только после 5 подтверждённых
  провалов и часа без успеха.

  Теперь он берёт интерфейс по умолчанию из `ConnectivityManager` сам, без VPN-службы.
- **Android: «нашёл N» в ходе проверки — это новые серверы за партию**, а не число
  повторно подтверждённых рабочих.
- **Квота на сервис поднята до 5** (YouTube, Telegram, Discord, универсальный): пока сервис
  ниже порога, автопоиск ищет под него.
- **Android: результаты прошлой проверки применяются один раз** (устранено двойное
  применение при старте), а автозапись списка и ручное добавление сервера больше
  не перезаписывают друг друга (`SaveNodes` под общим замком).

- **Android: рабочие серверы загружаются из своего файла первыми и сразу перепроверяются.**
  Порядок на запуске: `nodes-working.json` → перепроверка рабочих («Старт: рабочие
  перепроверены — 7, живых 7») → и только потом поиск новых и квоты. Рабочий список
  переживает перезапуск и не собирается заново поиском.
- **Рабочие серверы не пропадают из списка из-за проверок.** Результат последней удачной
  проверки сохраняется все 5 попыток: сервер удаляется только после 5 провалов подряд,
  а не после первого/третьего. Непроверенный — после второго подряд.
- **Счётчики в шапке считают по одной базе.** Общее число рабочих и значки сервисов берут
  серверы рабочего списка с подтверждённым доступом (свежесть проверки в счётчиках
  не учитывается, иначе они «таяли» бы сами по себе). Один сервер может открывать
  несколько сервисов, поэтому сумма значков больше общего числа.
- **Android: рабочее и непроверенное хранится отдельно.** Проверенные серверы лежат
  в маленьком `nodes-working.json` и переписываются после каждой проверки, а куча
  непроверенных — в общем кэше, не чаще раза в минуту.
- **Android: значок «рабочих серверов» показывает содержимое списка рабочих** —
  ровно то, что сохраняется в `nodes-working.json`. Найденные при проверке рабочие серверы
  сразу попадают в этот список и в файл, поэтому число на значке растёт по партиям,
  а не считается заново по всем найденным. Рядом — «+прибавилось −убыло».
- **Android: во время ручной проверки фоновая не работает.** Пока идёт «Проверить серверы»
  (5 партий), планировщик и обслуживание свои партии не запускают — иначе они отбирали
  `:probe` между партиями и ручной прогон стоял на месте.
- **Android: «Остановить поиск» — только для ручного прогона.** Фоновая проверка больше
  не делает кнопку «стопом»: нажатие «Проверить серверы» всегда запускает ручную проверку
  (фоновая партия при этом уступает место).
- **Рабочие серверы проверяются мягче (Windows и Android).** Первые два провала
  не стирают результат последней удачной проверки — счётчики не скачут из-за разовой
  ошибки сети. Рабочему серверу в проверке даётся вторая попытка, а TCP-отсев
  (грубая проверка на мобильной сети) больше не засчитывается рабочим как провал.
  Удаление — только после 5 провалов подряд, как и раньше.
- **Проверка не замирает на одном сервере:** у клиента Clash API таймаут 10 секунд вместо
  30 и свой предел на запрос задержки (timeout + 2,5 с).
- **Кэш: рабочий сервер с одним провалом больше не выбрасывается при загрузке**
  (Windows и Android): в текущей схеме это не «мусор», а сервер, ждущий перепроверки, —
  он удаляется только после 5 провалов подряд.
- **Windows: то же разделение кэша** (`NodeCacheWriter`): рабочие — в `nodes-working.json`
  после каждой проверки, непроверенные — в `nodes.json` не чаще раза в минуту.
  Правило «рабочий сервер удаляется только после 5 провалов» на ПК работало и раньше
  (скрытая проверка идёт в том же процессе с настоящими объектами серверов).
- **Android: рабочие серверы больше не удаляются после одного провала.** Процесс `:probe`
  разбирал ссылки в новые объекты и не знал прежний статус и счётчик провалов, поэтому
  считал рабочий сервер непроверенным и удалял его с первой неудачи. Теперь статус
  и `FailCount` едут вместе с запросом: рабочий удаляется только после 5 провалов подряд,
  как и на ПК.
- **Android: одно нажатие «Проверить серверы» прогоняет 5 партий по 200** — до 1000 серверов,
  с подписью «Партия 2 из 5» и общим итогом. Остановка прерывает и текущую партию, и очередь.
- **Android: рабочие серверы проверяются отдельным проходом** после поиска новых
  («Проверяю рабочие: 3 из 12»), а не занимают место в партиях поиска.
- **Android: фоновая проверка не забирает `:probe` у ручной** — пока идёт ручной прогон,
  планировщик свои партии не запускает.
- **Android: проверка больше не висит, если `:probe` умер.** Ожидание результата прерывается,
  если счётчики прогресса не меняются 100 секунд (раньше файл прогресса считался
  «живым» и ожидание длилось все 10 минут).
- **Android: приложение больше не зависает на старте и при нажатиях.** Счётчики сервисов,
  выбранный сервер и сводка на экране «Серверы» читают уже готовый снимок списка и не ждут
  разбора кэша или обновления источников. Раньше эти данные ждали общий замок, пока фон
  разбирал тысячи серверов, — отсюда были зависания на 5+ секунд и системные ANR.
- **Android: кнопка «Остановить поиск» срабатывает сразу.** Остановка больше не ждёт
  завершения текущей партии: проверка прерывается, процесс `:probe` завершается принудительно,
  а повторное нажатие «Проверить серверы» действительно запускает новую проверку.
- **Android: список серверов ограничен 5000** (было 12 000) — меньше памяти, быстрее старт
  и разбор кэша. Существующий кэш подрезается при первом запуске (миграция настроек, схема 4).
- **Android: партия проверки — 200 серверов** (было 100): меньше холодных запусков процесса
  `:probe`, меньше нагрузки на телефон.
- **Android: меньше нагрузки на сборщик мусора.** При подсчёте счётчиков больше не создаются
  строки на каждый сервер и каждый сервис; список серверов хранится готовым снимком.
- **Журнал Android дублируется в logcat** (тег `VieNLinkLog`): файл журнала на телефоне
  приватный, и без этого зависания проверки нельзя разобрать через `adb`.
- **В имени подключённого сервера больше нет Telegram-каналов и служебных меток.**
  Из отображения убираются `@каналы`, ссылки `t.me/...`, `TG:` и пустые разделители.
  Например, `GB 🇬🇧 | @NamiraConfigs | …` показывается как `GB 🇬🇧`.
  Если от имени остался только канал, показывается `IP:порт` сервера.
- **Android: `IP:порт` не дублируется**, если он уже есть в имени сервера.

## 1.3.4 — Windows и Android, 22.11.2026

- **Android: убраны нереализованные режимы обхода.** На странице «Обход» больше нет карточек
  «Обход Zapret» и «Свой обход DPI» с пометкой «в разработке»: на телефоне без root WinDivert

- **Проверка найденных серверов стала в разы быстрее.** Перед полной проверкой
  мёртвые `host:port` отсеиваются быстрым TCP-опросом (`NodePrecheck`, 96 соединений,

  ограничен 6 минутами: приложение не висит на «Проверяю серверы» полчаса, а продолжает
  следующим тактом. UDP-протоколы (Hysteria2/TUIC) TCP-отсев не затрагивает.
- **Переключение серверов учитывает выбранный сервис.** Если нажать «Универсальный»

  серверов выбранного сервиса нет, переключение идёт на следующий лучший из другого
  сервиса. При появлении нового сервера выбранного сервиса он встаёт первым в
  приоритете, а при работе на запасном сервере приложение плавно возвращается на него
  (тёплое переключение без перезапуска ядра, если сервер уже в конфиге).

  сервис — она ходит по кругу внутри его приоритета.
- **Проверка серверов во время работы VPN больше не удаляет рабочие серверы.**
  Прямая проверка в скрытом ядре (ПК) и в процессе `:probe` (Android) идёт мимо VPN —
  это подтверждено кодом и журналом. Исправлено три причины ложных провалов:
  проверка через поднятый прокси теперь идёт по универсальному Cloudflare и сервису,
  который сервер уже открывал (раньше — только по YouTube, и сервер, работающий через
  Telegram/Cloudflare, браковался и после пяти подключений удалялся); провал проверки
  живости больше не меняет статус сервера — статус и `FailCount` определяет только
  прямая проверка; граница свежести в фоновой проверке пересчитывается в каждом проходе,
  поэтому живые серверы не выпадают из счётчиков на десятки минут.

## 1.0.4-beta — 20.11.2026

Первая публичная бета под именем **VieNLink** (ранее проект назывался DomVPN, ещё раньше — MyrrProxy).

### Добавлено

- Кнопка «Подключить / Отключиться» в шапке и быстрое меню узлов в трее.
- Скорость и суммарный трафик сессии в шапке (Clash API `/traffic`).
- Страна и IP выхода после подключения.
- Замер скорости узла (~1 МБ через узел), колонка «Скорость» и выбор узла для видео по скорости.
- Kill switch: при падении ядра системный прокси остаётся на закрытом порту.
- Автозапуск при входе в Windows (`HKCU\...\Run`, старт в трее).
- Проверка и обновление ядра sing-box; версия ядра видна в «Общих».
- Пресеты сайтов: YouTube, Telegram, Discord, Instagram, Facebook, X.
- Снятие loopback-изоляции для приложений Microsoft Store (`CheckNetIsolation`).

### Изменено

- Повторы узлов склеиваются мягче: на один `хост:порт` остаётся до 4 вариантов,
  чтобы не терять рабочие аккаунты с общих CDN.
- Проверка «сайт открылся» строже: успех только при коде < 400.
- Health-check реже (90 с, после сбоя 25–120 с) и адаптивная параллельность проверки.
- Источники при ошибке прокси повторяются напрямую.
- Сбой узла во время операции не теряется — переключение откладывается.
- `sources.dat` шифруется DPAPI; старые открытые копии удаляются.
- Конфиг ядра с UUID удаляется при отключении и выходе.
- Узлы с `tls.insecure` помечаются «⚠» и не выбираются первыми.
- Логи пишут стек исключения; журналы ротируются по 2 МБ.
- `MainWindow` разбит на partial-классы; добавлены golden-тесты и CI.
- Версии схем `settings.json`, `nodes.json` и `mtproto.json`: старые файлы
  мигрируют, новые читаются с предупреждением в журнале — данные не сбрасываются.

### Айдентика

- Новое имя и иконка: V + кольцо-связка, палитра графит/мятный.
- Логотип-вордмарк и обложка для GitHub — в `branding/`.
- Статус «бета» в шапке, заголовке окна, «Общих» и установщике.
