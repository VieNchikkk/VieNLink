# История изменений

## 1.3.5 — Windows и Android, 22.11.2026

- **Рабочие серверы не пропадают из кэша по возрасту источника.** Раньше при загрузке
  кэша сервер, который не встречался в источниках дольше `KeepUnseenNodeDays` (7 дней),
  отбрасывался даже со статусом «рабочий». Теперь возраст источника применяется только
  к непроверенным серверам: рабочий остаётся, пока его не забракует перепроверка.
  Это важно после обновления приложения или долгого простоя.

## 1.3.4 — Windows и Android, 22.11.2026

- **Android: убраны нереализованные режимы обхода.** На странице «Обход» больше нет карточек
  «Обход Zapret» и «Свой обход DPI» с пометкой «в разработке»: на телефоне без root WinDivert
  и kernel-перехват не работают, их задачу решает TUN-обход. Остался только TUN-обход (бета).
  Экран приложения зафиксирован в портретной ориентации: приложение не включает автоповорот
  и не меняет системную настройку — окна просто не крутятся по датчику.
- **Проверка найденных серверов стала в разы быстрее.** Перед полной проверкой
  мёртвые `host:port` отсеиваются быстрым TCP-опросом (`NodePrecheck`, 96 соединений,
  2 с на адрес, один опрос на endpoint) — в пробное ядро попадают только отвечающие
  адреса. Параллельность полной проверки поднята: 12 в простое, 8 без VPN, 6 при
  подключённом прокси, 16 для ручной партии; внутри партии серверы перемешиваются
  по источникам, чтобы один большой мёртвый список не занимал все места. Один фон-такт
  ограничен 6 минутами: приложение не висит на «Проверяю серверы» полчаса, а продолжает
  следующим тактом. UDP-протоколы (Hysteria2/TUIC) TCP-отсев не затрагивает.
- **Переключение серверов учитывает выбранный сервис.** Если нажать «Универсальный»
  (или YouTube/Telegram/Discord) и сервер упадёт, следующий выбирается из серверов
  этого же сервиса — сначала лучший по задержке и качеству. Только когда живых
  серверов выбранного сервиса нет, переключение идёт на следующий лучший из другого
  сервиса. При появлении нового сервера выбранного сервиса он встаёт первым в
  приоритете, а при работе на запасном сервере приложение плавно возвращается на него
  (тёплое переключение без перезапуска ядра, если сервер уже в конфиге).
  Правило общее для ПК и Android (`NodeFailover`): свежесть проверки обязательна,
  «Только мои» соблюдается. Кнопка «Сменить сервер» больше не сбрасывает выбранный
  сервис — она ходит по кругу внутри его приоритета.
- **Проверка серверов во время работы VPN больше не удаляет рабочие серверы.**
  Прямая проверка в скрытом ядре (ПК) и в процессе `:probe` (Android) идёт мимо VPN —
  это подтверждено кодом и журналом. Исправлено три причины ложных провалов:
  проверка через поднятый прокси теперь идёт по универсальному Cloudflare и сервису,
  который сервер уже открывал (раньше — только по YouTube, и сервер, работающий через
  Telegram/Cloudflare, браковался и после пяти подключений удалялся); провал проверки
  живости больше не меняет статус сервера — статус и `FailCount` определяет только
  прямая проверка; граница свежести в фоновой проверке пересчитывается в каждом проходе,
  поэтому живые серверы не выпадают из счётчиков на десятки минут.

## 1.3.3 — Windows и Android, 22.11.2026

  «Сменить сервер» и «Поделиться сервером», на всю ширину, зелёная с иконкой «+»:

- **Подписи кнопок шапки больше не ломаются по слогам** («Подел/иться»): переносы отключены,

  актуальные правила перенесены в `AGENTS.md`.

## 1.3.2 — Windows и Android, 22.11.2026

- **Счётчики обновляются раз в минуту, серверы проверяются каждые 5 минут.**
  Окно свежести и интервал перепроверки — 5 минут; узел берётся в работу немного
  раньше истечения окна. Windows обновляет сводку таймером раз в минуту, Android —
  при каждом обновлении шапки. После запуска и возврата в приложение ранее рабочие
  серверы перепроверяются сразу, поэтому счётчики не висят нулями.
- **«Поделиться сервером» отдаёт только адрес `IP:порт`.** Ни длинных ссылок,
  ни JSON, ни флагов и названий каналов: на Android открывается системный лист,
  на ПК строка копируется в буфер.
- **Android: «Добавить сервер» в шапке.** Под кнопками «Сменить сервер» и «Поделиться»
  появилась кнопка на всю ширину: ссылка с ключом (`vless://`, `vmess://`, `trojan://`,
  `ss://`, `hysteria2://`) добавляется в список и проверяется вне общей очереди, а `IP:порт`
  находит уже известный сервер. Найденный рабочий сервер сразу подключается.
- **Android: сбор и проверка MTProto видны и останавливаются.** На странице
  Telegram MTProtoProxies кнопки «Собрать» и «Проверить» показывают ход работы
  в строке состояния и превращаются в «Остановить сбор» / «Остановить проверку»;
  отмена не теряет уже собранные и проверенные прокси.
- **Кнопки сервисов переподключают при смене сервиса.** Если подключён
  «Универсальный» и нажать «YouTube», текущий сервер исключается из выбора —
  приложение действительно переключается на сервер с доступом к YouTube.
  «Универсальный» больше не висит минутами: ожидание занятой проверки ограничено
  90 секундами с понятным статусом.
- **Кнопка «Остановить все процессы» / «Запустить все процессы»** в настройках
  (Android и ПК): выключает и снова включает проверку серверов, MTProto,
  обслуживание по будильнику, автообновления и автопереключение. Туннель и ручные
  действия продолжают работать; состояние сохраняется между запусками.
- **Android: вкладка «Общие» убрана.** Проверка обновлений, очистка кэша серверов
  и настройки VPN — в «Настройках»; версия, лицензии, документы и пути — в
  «О программе», без дубликатов. Нижних вкладок теперь четыре.
- **Android: шапка и терминология.** «Проверить серверы», «Сменить сервер»,
  «Поделиться сервером» — три оформленные кнопки; отдельная «Скорость» убрана
  (скорость и так в метриках). При отключённом VPN пинг, скорость, выход и трафик
  показываются как «—». Слово «узел» в интерфейсе заменено на «сервер».
- **Устранено зависание Android при переключении серверов.** Тяжёлая сортировка
  тысяч серверов и сборка конфига вынесены с UI-потока: второе нажатие «Сменить
  сервер» больше не приводит к ANR. Оценка маскировки кэшируется, кэш серверов
  пишется компактно, сводки считаются одним проходом.
- **Стабильность фона.** Android: обслуживание по будильнику через
  `SetAndAllowWhileIdle`, защита от наложения тактов, применение результатов
  `:probe` после убийства процесса, откат статусов при обрыве сети. ПК: фоновый
  такт не роняет приложение, откат партии при недоступном интернете работает для
  любого размера партии, ручное переключение не засчитывается как провал.
- **Настройки по умолчанию:** виджет ПК показывается при запуске, все источники
  включены, партия проверки в простое на ПК — 200 серверов. Android-поиск новых
  серверов в стабильном состоянии — раз в 10 минут.
- **Обновления Android:** резервная atom-лента релизов и зеркала APK; неудачная
  проверка больше не откладывает следующую на 6 часов. На ПК установщик тоже
  скачивается с зеркал.

## 1.3.1 — Windows и Android, 22.11.2026

- **Исправлен краш Android после автопереключения сервера.** Приложение падало
  с `SIGSEGV` в `libmonodroid` (`open_from_bundles`) при ленивой загрузке сборки
  `System.Net.NameResolution.dll` из фоновых потоков (health-check, проверка выхода/скорости,
  обслуживание, `:probe`) — они одновременно впервые трогали DNS-сборку и гонялись
  между собой. Теперь сетевые сборки прогреваются один раз на главном потоке при старте,
  до запуска фоновых задач.
- **Счётчики в значках больше не врут.** Окно свежести узла было 6 часов, а перепроверка
  шла раз в 30 минут — значок обещал «8» рабочих узлов, а кнопка после живой проверки
  не находила ни одного (узлы успевали умереть). Окно свежести теперь равно интервалу
  перепроверки и измеряется в минутах, интервал сокращён до 15 минут. Число на значке
  и результат кнопки совпадают.

## 1.3.0 — Windows и Android, 22.11.2026

- **MTProto-прокси теперь собираются и с сайтов**, а не только из Telegram-каналов.
  Добавлен тип источника `MtProto`: GitHub-списки `tgmtproxy` (881 прокси в проверке),
  `SoliSpirit/mtproto` (303), `suryadev-sm` (27) и JSON-агрегатор `Airuop` (15).
  Парсер понимает ссылки `t.me/proxy`, блоки «Server/Port/Secret» и JSON (в том числе
  с экранированными слэшами). Новые сайты добавляются включёнными при обновлении,
  а в сборе идут первыми — Telegram-каналы через RSS могут тормозить.
- Сайты MTProto не попадают в сбор узлов: их читает только `MtProtoService`.
- **Кнопка «Дальше»** в шапке: переключает на следующий проверенный узел по возрастанию
  пинга без разрыва соединения (Clash selector), а при отсутствии в конфиге — полным
  переподключением. «Лучший» и автопереключение теперь выбирают самый быстрый свежий узел.

**Android:**

- **MTProto-прокси собираются с сайтов**, а не только из Telegram-каналов:
  GitHub-списки `tgmtproxy`, `SoliSpirit/mtproto`, `suryadev-sm` и JSON `Airuop`.
  Разбор ссылок `t.me/proxy`, блоков `Server/Port/Secret` и JSON с экранированными
  слэшами; новые источники включаются автоматически и читаются первыми.
- Группа источников переименована в «Telegram-прокси (каналы и сайты)».
- **Кнопка «Дальше»** рядом со «Скоростью»: следующий проверенный узел по пингу,
  переключение через Clash selector без перезапуска TUN; если узла нет в конфиге —
  пересборка конфига.
- Автопереключение проверяет узел каждые 20 секунд и выбирает самый быстрый
  загруженный узел; TUN и открытые приложения не перезапускаются.

## 1.0.15-beta — Windows, 21.11.2026

- **Честные счётчики сервисов.** Значки YouTube/Discord/Telegram/универсального доступа
  и кнопки быстрого подключения считают по одному правилу: только свежая проверка,
  `Working`, подтверждённый доступ и «Только мои». Устаревший кэш больше не обещает узел,
  которого нет; «универсальный» — только реально открывшийся Cloudflare.
- **Рабочие узлы перепроверяются каждые 30 минут** и сразу выпадают из счётчиков при
  провале; удаляются после 5 провалов подряд. Раньше они висели часами, потому что стояли
  в очереди после тысяч непроверенных.
- **Квоты и фоновый поиск:** 10 рабочих узлов и по 2 на каждый сервис (YouTube, Telegram,
  Discord, универсальный). Пока квота не набрана — такт 1–2 минуты, фокус сервиса
  меняется по кругу, источники обновляются не реже раза в 30 минут.
- **Строка проверки** показывает «Проверено N из M: рабочих K» без перечисления сервисов;
  ход фоновой проверки виден в шапке.
- **Исправлен перенос результатов** между разными аккаунтами на одном хост:порту и потеря
  `UniversalOk`/`DiscordOk`/`OpenDomains`/`FailCount` при обновлении источников.
- **Быстрое подключение:** если свежих узлов для сервиса нет, приложение сначала проверяет
  подходящих кандидатов скрытым ядром и только потом показывает сообщение.

## 1.2.0 — Android, 21.11.2026

- **Магазинная сборка.** `build/publish-store.ps1` собирает APK для RuStore и AAB для
  Google Play без `REQUEST_INSTALL_PACKAGES` и самообновления (`StoreBuild=true`).
  GitHub-APK по-прежнему обновляет себя сам: это две разные сборки.
- **Поиск узлов можно остановить.** Кнопка шапки во время проверки называется
  «Остановить поиск»: отменяет текущую партию, гасит процесс `:probe` и приостанавливает
  фоновый поиск до следующего явного действия («Проверить узлы», кнопка сервиса,
  «Проверить» на экране «Узлы»). «Отключить» во время поиска узла тоже его останавливает.
- **Честные счётчики и квоты.** Значки сервисов и кнопки используют одно правило
  (`NodeAvailability`): только свежая проверка, `Working`, подтверждённый доступ и
  «Только мои». «Универсальный» — только реально открывшийся Cloudflare.
- **Рабочие узлы перепроверяются каждые 30 минут** и сразу выпадают из счётчиков при
  провале; удаляются после 5 провалов подряд.
- **Квота на каждый сервис — 2 узла** (YouTube, Telegram, Discord, универсальный).
  Пока она не набрана, поиск идёт чаще: Windows — раз в 1–2 минуты с ротацией сервисов,
  Android — партиями по 150 с ротацией фокуса. Источники обновляются не реже раза в 30 минут.
- **Исправлен перенос результатов** между разными аккаунтами на одном хост:порту и потеря
  `UniversalOk`/`DiscordOk`/`OpenDomains`/`FailCount` при обновлении источников.
- **Меньше лишнего в строке проверки**: «Проверено N из M: рабочих K» без перечисления
  сервисов; ход фоновой проверки виден в шапке.

## 1.0.4-beta — 20.11.2026

Первая публичная бета под именем **VieNLink** (ранее проект назывался DomVPN, ещё раньше — MyrrProxy).

### Добавлено

- Кнопка «Подключить / Отключиться» в шапке и быстрое меню узлов в трее.
- Скорость и суммарный трафик сессии в шапке (Clash API `/traffic`).
- Страна и IP выхода после подключения.
- Замер скорости узла (~1 МБ через узел), колонка «Скорость» и выбор узла для видео по скорости.
- Kill switch: при падении ядра системный прокси остаётся на закрытом порту.
- Автозапуск при входе в Windows (`HKCU\...\Run`, старт в трее).
- Проверка и обновление ядра sing-box; версия ядра видна в «Общих».
- Пресеты сайтов: YouTube, Telegram, Discord, Instagram, Facebook, X.
- Снятие loopback-изоляции для приложений Microsoft Store (`CheckNetIsolation`).

### Изменено

- Повторы узлов склеиваются мягче: на один `хост:порт` остаётся до 4 вариантов,
  чтобы не терять рабочие аккаунты с общих CDN.
- Проверка «сайт открылся» строже: успех только при коде < 400.
- Health-check реже (90 с, после сбоя 25–120 с) и адаптивная параллельность проверки.
- Источники при ошибке прокси повторяются напрямую.
- Сбой узла во время операции не теряется — переключение откладывается.
- `sources.dat` шифруется DPAPI; старые открытые копии удаляются.
- Конфиг ядра с UUID удаляется при отключении и выходе.
- Узлы с `tls.insecure` помечаются «⚠» и не выбираются первыми.
- Логи пишут стек исключения; журналы ротируются по 2 МБ.
- `MainWindow` разбит на partial-классы; добавлены golden-тесты и CI.
- Версии схем `settings.json`, `nodes.json` и `mtproto.json`: старые файлы
  мигрируют, новые читаются с предупреждением в журнале — данные не сбрасываются.

- Новое имя и иконка: V + кольцо-связка, палитра графит/мятный.
- Логотип-вордмарк и обложка для GitHub — в `branding/`.
