**1.3.1 (22.11.2026) — два исправления по жалобам владельца.**
- **Краш Android после автопереключения.** В `/data/tombstones/` два дампа
  `com.vienlink.app`: `SIGSEGV` в `libmonodroid` (`open_from_bundles`) на `.NET TP Worker`
  при ленивой загрузке `System.Net.NameResolution.dll`. Причина — гонка первой загрузки

  `Maintenance`, `:probe`). Фикс: `VieNLinkApp.WarmNetworkAssemblies` трогает сетевые типы
  на главном потоке при старте, до запуска фоновых задач.
- **Счётчики значков врали** («пишет 8, а подключиться нечем»): окно свежести было 6 часов
  (`IdleRecheckHours`), а перепроверка — 30 минут. `NodeAvailability` теперь считает
  свежесть в минутах, окно = `NodeLimits.WorkingRecheckMinutes` (15 минут), все вызовы
  `IsUsable` (Windows и Android) переведены на него; интервал перепроверки сокращён
  с 30 до 15 минут.
- Сборка: Windows 0 ошибок / 0 предупреждений; Android 0 ошибок (57 прежних предупреждений);
  `SelfTest -- parsers/checkconfigs/statuslogic` — «всё в порядке». Исходники 1.3.1
  в `main`; теги `v1.3.1-beta`/`v1.3.1-android` указывают на последний коммит с этими правками.

## Аудит паритета ПК ↔ Android (21.11.2026, вечер)

Сверены `AppSettings`, экраны и автоматика. Исправлено в Android:
- конфиг больше не наследует Windows-правила `AppRouteMode/AppList` (клонируется и
  принудительно `All`), иначе `process_name` с именами Windows-процессов уводил трафик напрямую;
- выбор узла приведён к Windows: Telegram-приоритет, личные, домены, `NodeRanking`, задержка,
  `MaxDelayMs`; для кнопок сервисов не подставляются узлы без нужного доступа;
- `ConnectOnlyMine` фильтрует конфиг, а не только выбор;
- добавлены настройки `AutoDiscoverSources/Hours`, `AutoRefreshMinutes`, `MaxTotalNodes`,
  `MaxDelayMs`, `ShowTraffic/ShowExitInfo`, `DefaultSni`, `TunStrictRoute`;
- `AutoRefreshMinutes` (120) теперь реально управляет фоном; `TestAfterRefresh` запускает
  проверку после обновления; уменьшение `MaxTotalNodes` подрезает кэш сразу;
- MTProto: сбор/проверка каждые 10 минут в процессе (`MtProtoScheduler`), после сбора сразу
  проверяются новые прокси; фоновая проверка узлов вынесена в foreground-службу `:probe`
  (больше нет `BackgroundServiceStartNotAllowedException`);
- в шапке реально показываются/скрываются выход, скорость и трафик сессии по настройкам;
  кэш выхода/скорости сбрасывается при смене узла;
- поле ссылки сохраняется при переключении вкладок; проверка обновлений идёт через узел,
  если он подключён.

## Аудит Android (21.11.2026, после порта 1.1.0)

Разбор кода Android-клиента на ошибки, конфликты, утечки памяти и производительность.

**Исправлено в коде:**
1. Утечка ресурсов: при переключении с TUN-обхода на прокси-узел форвардер
   `TlsFragmentForwarder` не останавливался — его порт/сокет оставались заняты до
   следующего отключения. Теперь `TunnelService.StartCore` при обычном (не bypass)
   запуске останавливает `ForwarderHost`.
2. Оптимизация шапки: счётчики сервисов пересчитывались через `NodeStore.Snapshot()`
   (копия до 12 000 узлов + 4 LINQ-прохода) каждые ~3 с. Добавлен `NodeStore.Summary()`
   — один проход под блокировкой без аллокации копии.
3. DNS-транспорт `LocalDnsTransport.Exchange`: зависший `ReceiveAsync` при таймауте
   оставлял фоновую задачу до закрытия сокета. Переведён на `CancellationTokenSource`
   с отменой приёма/отправки по таймауту (4 с), висящие задачи больше не плодятся.
4. Возможный NRE в `MaintenanceReceiver.OnReceive`: `GoAsync()` мог вернуть `null`,
   `pending.Finish()` разыменовывал без проверки — заменено на `pending?.Finish()`.

**Проверено и признано безопасным (без правок):**
- Память: `CoreRuntime`/`LibBoxPlatform`/`LibBoxServerHandler` — осознанные синглтоны
  процесса (один `CommandServer`); Handler/таймеры снимаются в `OnPause`/`OnDestroy`;
  статические кэши `NetworkProbe` ограничены одной записью; `:probe` завершает процесс
  после записи результатов. Критических утечек не найдено.
- Конфликты режимов: TUN-обход ↔ прокси-узел взаимоисключающие (проверка `IsBypassMode`
  в `ProbeClient`/`NodeStore.PickVerifiedAsync`); параллельные проверки узлов гасятся
  семафором `ProbeClient.Gate` (BusyError). Ограничение платформы — один VPN на устройство
  (`VpnService`), при активном чужом VPN наше подключение отзывает его и наоборот — это
  ожидаемо, обрабатывается `OnRevoke`.
- Конфликты с другими приложениями: `TunnelService`/`TunnelTileService`/`BootReceiver`
  экспортированы точечно с минимальными permission (`BIND_VPN_SERVICE`,
  `BIND_QUICK_SETTINGS_TILE`, `BOOT_COMPLETED`); `<queries>` ограничен MAIN/LAUNCHER.

**Документация:** в `AGENTS.md` дополнена карта файлов Android (`VieNLinkApp`,
`LicenseActivity`, `MtProtoScheduler`, `ProbeModels`, `DefaultNetworkCallback`,
`NetworkInterfaceIterator`), уточнён состав действий уведомления. Здесь приведена
актуальная версия APK (1.1.0).
