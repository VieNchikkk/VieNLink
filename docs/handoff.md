## Сборка и проверки

Готовый Windows-релиз 1.0.7: `release\VieNLink-1.0.7-win-x64` (+ ZIP 100,8 МБ) и
`release\VieNLink-1.0.7-setup.exe` (92,9 МБ), exe и установщик подписаны (`CN=VieN`), внутри
`core\`, `zapret\`, `LICENSE` и `THIRD-PARTY-NOTICES.md`. Опубликован на GitHub:
https://github.com/VieNchikkk/VieNLink/releases/tag/v1.0.7-beta (ZIP, установщик,
`SHA256SUMS.txt`, статус Pre-release).

Windows (системный `dotnet`):

```powershell
dotnet build VieNLink\VieNLink.csproj          # Windows-клиент
dotnet build VieNLink.SelfTest\VieNLink.SelfTest.csproj
dotnet run --project VieNLink.SelfTest -- parsers
dotnet run --project VieNLink.SelfTest -- checkconfigs
dotnet run --project VieNLink.SelfTest -- desync
```

Android (локальный SDK):

```powershell
$dotnet = "$env:LOCALAPPDATA\dotnet\dotnet.exe"
& $dotnet build VieNLink.Android\VieNLink.Android.csproj -c Debug `
    -p:AndroidSdkDirectory="$env:LOCALAPPDATA\android-sdk" `
    -p:JavaSdkDirectory="$env:LOCALAPPDATA\jdk17"
$adb = "$env:LOCALAPPDATA\android-sdk\platform-tools\adb.exe"
& $adb install -r VieNLink.Android\bin\Debug\net10.0-android\com.vienlink.app-Signed.apk
```

## Грабли, которые уже стоили времени

- Android: `Libbox.Setup` обязателен; `StartOrReloadService` не принимает `null`;
  `FindConnectionOwner` не возвращает `null`; маршрут `0.0.0.0/0`; DNS-сокет `protect(fd)`;
  один `CommandServer` на процесс (второй ломает `cache-file`).
- Clash API: при работающем туннеле проверять только загруженные узлы, иначе ложные провалы.
  Фоновая проверка Windows обходит это отдельным ядром `HiddenProbeService` (порты 22000+).
- Windows: не убивать `VieNLink.exe` при включённом системном прокси — `ProxyEnable=1`
  останется на мёртвом порту и интернет пропадёт. Сначала «Отключиться» (или дать
  `SystemProxy.RecoverIfNeeded` восстановить при следующем запуске). В этом чате после
  принудительного закрытия пришлось вручную вернуть `ProxyEnable=0`, `ProxyServer=''`,
  `ProxyOverride=<local>` и вызвать `InternetSetOption`.
- `adb`: bool-extra — `--ez`, string — `-e`; Java-имена activity в
  `obj\Debug\net10.0-android\android\AndroidManifest.xml` (`crc64701940d33722e542.*`).
- `adb shell run-as com.vienlink.app am startservice …` требует `--user 0`, иначе
  `SecurityException` про `INTERACT_ACROSS_USERS`. Так можно нажать «Лучший»/«Отключить»
  без открытия шторки — это те же `PendingIntent`-действия службы.
- ColorOS отдаёт `BOOT_COMPLETED` с задержкой ~40 с и игнорирует `cmd statusbar add-tile`;
  `click-tile` для плитки, которой нет в шторке, ничего не делает. Плитка — ручная проверка.
- Android-экраны в Debug экспортированы для adb, в Release — нет.
- Tele2: открытый DNS подменяется, `1.1.1.1`/`8.8.8.8` не работают; Яндекс DNS `77.88.8.8`
  резолвит, но TCP к Google/Cloudflare не открывается (IP/ASN-блок).
- WinDivert: после изменения пакета нужны корректные чексуммы; для IP-фрагментов
  использовать `SendRaw` (без `WinDivertHelperCalcChecksums`), TCP-чексумму не трогать.
