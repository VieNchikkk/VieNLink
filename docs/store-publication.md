Пакет: `com.vienlink.app` · версия **1.3.1 (versionCode 10301)**.
Магазинная сборка (без `REQUEST_INSTALL_PACKAGES` и самообновления):

```powershell
powershell -File build\publish-store.ps1
```

Результат в `release\`:

- `VieNLink-1.3.1-store.apk` — для RuStore (и ручной установки);
- `VieNLink-1.3.1-store.aab` — для Google Play;
- рядом `*.sha256`.

запрещают приложению устанавливать обновления самостоятельно.

## RuStore

### Что нужно для аккаунта

1. **VK ID** и регистрация в [консоли RuStore](https://console.rustore.ru).
2. Тип аккаунта: физическое лицо, самозанятый, ИП или организация.
   Для физлица кабинет запросит паспортные данные и ИНН; для ИП/ООО — реквизиты.
   Для **бесплатных** приложений платёжные данные не нужны.
3. Принять соглашение разработчика и правила магазина.
4. Контактный e-mail, который увидит модерация и пользователи.

### Требования к приложению

- Подписанный APK, `versionCode` больше предыдущего (сейчас 10301).
- `targetSdk` не ниже требований RuStore (у нас 36), 64-битные библиотеки (arm64-v8a есть).
- Приложение не должно обновлять себя в обход магазина — магазинная сборка это соблюдает.
- Публичная **политика конфиденциальности** (URL) и достоверное описание.
- Возрастной рейтинг и категория.
- Иконка 512×512, 2–10 скриншотов 1080×1920 и выше.
- Отсутствие рекламы/покупок, если их нет (у нас нет).
- Соответствие законодательству РФ. Для сетевых клиентов важно: реклама средств
  обхода блокировок ограничена (408-ФЗ), поэтому в карточке используются нейтральные
  формулировки из [store-listing.md](store-listing.md).

### Шаги

1. Создать приложение → «Загрузить APK» → `VieNLink-1.3.1-store.apk`.
2. Заполнить карточку: название, краткое/полное описание, категория «Инструменты»,
   теги, возрастной рейтинг 18+, политика конфиденциальности, e-mail.
3. Загрузить иконку и скриншоты из `store/`.
4. Отправить на модерацию. Обычно 1–3 рабочих дня.
5. После публикации обновления — новый APK с `versionCode` +1 и тем же ключом подписи.
   Опционально можно подключить RuStore Update SDK (встроенные обновления магазина);
   текущая магазинная сборка просто полагается на обновления из кабинета.

## Google Play

### Что нужно для аккаунта

1. **Google Play Console** — разовый платёж $25 и верификация личности
   (для организаций — D-U-N-S).
2. Для новых **личных** аккаунтов Google требует **закрытое тестирование**
   (обычно 12 тестеров в течение 14 дней) до доступа к production. Для организаций
   это требование снимается.
3. Согласие с политиками, включая правила для VPN-приложений.

### Требования и особенности

- Загружается **AAB** (`VieNLink-1.3.1-store.aab`), не APK.
- **Play App Signing**: наш JKS используется как upload key; хранить его обязательно.
- В манифесте **нет** `REQUEST_INSTALL_PACKAGES` и самообновления — это требование Play.
- `targetSdk` 35+ (у нас 36), 64-bit, без `QUERY_ALL_PACKAGES` (используется `<queries>`).
- **Data safety**: данных не собираем, рекламы и трекеров нет, шифрование при передаче.
- **Контент-рейтинг** (IARC) и **VPN-декларация** (VpnService — основная функция).
- **Foreground service** `specialUse`/`dataSync` — заполнить обоснование в разделе
  «Разрешения и службы».
- Политика конфиденциальности (публичный URL) и контактный e-mail.
- Иконка 512×512, feature graphic 1024×500, 2–8 скриншотов.

### Шаги

1. Создать приложение, язык по умолчанию, название и категория.
2. Включить Play App Signing, загрузить AAB в закрытое тестирование.
3. Заполнить Data safety, контент-рейтинг, VPN- и foreground-декларации.
4. Загрузить медиа и тексты из [store-listing.md](store-listing.md).
5. Провести закрытое тестирование (если требуется), затем production rollout.

## Ключ подписи

- Ключ: `%LOCALAPPDATA%\VieNLink\signing\vienlink-android.jks`, пароль рядом
  (`android-signing.pass`). В репозиторий не попадает.
- Все сборки (GitHub, RuStore, Play upload) подписываются **одним ключом**.
- `versionCode` только растёт. Для Play дополнительно хранится upload key в Play Console.
- Потеря ключа = невозможность обновить уже установленное приложение.

## Политика конфиденциальности

Файл: [privacy.md](privacy.md). Чтобы получить публичный URL:

1. В репозитории GitHub → Settings → Pages → Source: `Deploy from a branch`,
   ветка `main`, папка `/docs`.
2. Через 1–2 минуты страница будет доступна:
   `https://vienchikkk.github.io/VieNLink/privacy.html`
   (GitHub Pages отдаёт Markdown как HTML только через Jekyll; для надёжности можно
   переименовать файл в `docs/privacy.html` или добавить `index.html`).

Пока Pages не включён, в карточке можно указать GitHub-ссылку на файл политики.
