# Handoff: Windows-часть

Файл для случая, когда Windows-часть ведёт отдельная сессия/агент (сейчас проект
ведёт один агент, но границы полезно держать). Общий контекст: `AGENTS.md` →
`docs/plan-2026.md` §0 → `docs/handoff.md`.

## Границы (важно при параллельной работе)

- Можно менять: `VieNLink/**`, `VieNLink.SelfTest/**`, `build/**` (только Windows-скрипты),
  этот файл.
- **Нельзя менять:** `VieNLink.Android/**` — им занимается Android-агент.
- `VieNLink.Core/**` — общий. Менять только по явной необходимости и после записи
  в `docs/handoff.md` строки `Core: <что изменено>`: Android-агент тоже собирает Core.
  Если возможно — сначала согласовать с пользователем.
- `docs/plan-2026.md` и `docs/handoff.md` — общие: добавлять только свои строки/абзацы,
  не перезаписывать файл целиком (второй агент может писать одновременно).
- Сборка: не запускать `dotnet build VieNLink.slnx` одновременно с Android-сборкой
  (общий `VieNLink.Core/bin`). При конфликте — подождать или собрать с отдельным
  `-p:OutputPath` в temp. Перед сборкой закрыть запущенный `VieNLink.exe`.
- Сеть: системный прокси/WinDivert влияют на всю машину. Не включать их, пока
  Android-агент тестирует сеть (adb по USB не страдает, но лучше не одновременно).

## Состояние Windows-части

- WPF-клиент собирается, `SelfTest` проходит `parsers`, `checkconfigs`, `desync`.
- «Свой обход DPI» (WinDivert): стратегии fake/multidisorder (TTL 128/64/2/4/8),
  split/disorder, QUIC-фейк, автоподбор. Требует прав администратора.
- Последняя добавленная техника: **IP-фрагментация ClientHello** (`DesyncTcpMode.IpFrag`):
  крупный ClientHello → фрагменты по 1200 байт, маленький → примерно пополам; TCP-поток
  не меняется, IP-чексумма пересчитывается, отправка через `SendRaw` без
  `WinDivertHelperCalcChecksums`.
- `desynclive` расширен на `IpFrag`.

- IP-фрагментация: YouTube `0`, Discord `0`, Cloudflare `204`, видео `0`, разрезов 35.
- После остановки прямой интернет — `204`.

## Следующие шаги

   где блок не по IP: сравнить `IpFrag` с fake/multidisorder по объёму и YouTube.
2. Остальные техники фазы 4.1: `wssize`, `hopbyhop`/`destopt` (IPv6), `synack`,

3. Фаза 4.3: автоподбор по объёму (сколько байт проходит, стабильность 10 с).
4. Фаза 1.1: измерение объёма при проверке узлов (`TestUrl` сейчас даёт только RTT).
5. Фаза 3: цепочки «мост → выход» — по плану.
6. Правовые 0.4–0.5 (Windows-поставка): лицензия zapret, тексты в `licenses\`,
   проверка на секреты.

## Грабли (Windows)

- `sing-box` не понимает BOM — конфиг только UTF-8 без BOM.
- Перед сборкой закрыть `VieNLink.exe`, иначе `bin` заблокирован.
- WinDivert: после правки пакета нужны корректные чексуммы. Для IP-фрагментов нельзя
  звать `WinDivertHelperCalcChecksums` (портит непервые фрагменты) — использовать `SendRaw`.
- `process_name`-правило обязательно в TUN-обходе, иначе форвардер замыкается сам на себя.
- Проверка «страница открылась» не равна «узел годится для видео»: ТСПУ морозит TCP по объёму.
